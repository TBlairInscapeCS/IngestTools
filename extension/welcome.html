How a job flows

Request
Load the email, confirm the client, and review requested IDs here. Outlook folder rules and recognized sender domains guide detection; manual selection wins. Trackerless clients hide the tracker and use Identify email IDs. Otherwise verify Document, worksheet, ID, and owner before matching. Override Match source under Advanced request options. Keep original delivery HTML for links.
↓
Files
Find files discovers direct links, ER deliveries, or open-page candidates without downloading. Review, then press Download files. ER auto-search expands 2 → 7 → configured days (default 14) as needed. Yangaroo search uses the delivery email's per-spot Download links or an open Yangaroo page - review matches before downloading. Stop halts queueing and cancels tracked in-flight downloads; completed files remain.
↓
Ingest
Feed files handles the standard batch; Feed ticker files handles the separate video-only batch. Feeding or picking files also writes the job manifest when needed so sheet-flagged tickers still auto-build. Check & preview shows Reporting ID and Portal Title separately, including ticker suffixes. Title defaults to ID unless rules say otherwise. Review the fill profile under more → fill before Accept fills. Tracker filenames can identify files whose ID/title differs. Ambiguous matches stay unfilled. Check filled/queued counts and review metadata differences, including Advertiser, Brand, and Vertical. BEGIN INGEST stays your click.
↓
Confirm
Verify & draft prepares Jira content; review gaps and proof before approving a post. Email sign-offs stay in the request copy, not as creative titles in the Ingest list. Copy and send the reply yourself. Both editable draft fields have Clear. Trackerless email matches automatically draft an acknowledgment from IDs or filenames; no sheet is needed. Redraft also works before Match. Choose Ingested + IDs only after actual ingest; trackerless confirmations omit sheet updates and use client ticker suffixes. An acknowledgment is not proof that files have been ingested.

First run

The panel shows four color-coded folder tabs, left to right: Request, Files, Ingest, and Confirm. Each page uses its tab's color. The sticky job summary separates identified IDs, located files, downloads completed this run, and verified reporting IDs (including tickers). Follow the suggested next-action button, or jump to any step. It never approves fills, posts Jira, sends replies, or begins ingest for you.

I already have the files searches local media. Use portal file picker takes you to the portal to select/drop files yourself, without needing a manifest. I already ingested them checks actual records. Stop downloads stays in the header during queueing and active downloads, even while viewing another step.

Client guidance/rules and advanced controls stay collapsed. Advanced settings → Show all steps (advanced) restores the expanded view and remembers your preference. Clear all clears the request, evidence, counters, previews, visible errors, and notifications after downloads finish or are stopped. Selecting a different request also dismisses old alerts and collapses Log. Saved diagnostic logs, sign-ins, and settings are kept; media and portal records are not deleted.

  1. Load the request and confirm the selected client.
  2. Check the tracker's Document title, or select No tracking sheet — email IDs only. ComScore and SimulMedia are trackerless.
  3. Press Run all to prepare matches and discover files, or work module by module. Run all does not automatically download media.
  4. Review the candidates, then press Download files. Watch the module status lines and progress bars instead of repeatedly clicking.
  5. Preview and accept portal fills, begin ingest yourself, then verify and review Jira/reply drafts.

Before an email arrives, a tracker-backed request can start from N pending row(s) — use as requested IDs. Review the pending set and recent-date filter before discovery.

Continue after manual work

Every module can be used independently. SimulMedia defaults to no tracker and mixed Comcast/Extreme Reach delivery. Choose Search → Comcast email to read matching Spot/Download links from open Outlook messages, or Downloads / Ingest to find recent media by request ID.

Feed files can find unique matches in Downloads or Ingest without a manifest and without moving the files. Ambiguous duplicates need Use portal file picker. Discovery alone does not build missing tickers.

After a manual upload/ingest, go straight to Verify & draft. Later file/record evidence overrides earlier misses for the active request. The auto-reply distinguishes completed, processing, failed, and still missing IDs. Edited drafts are kept; use Auto draft → Redraft to replace them. Client rules can exclude discovery from Run all.

Client rules and naming

Under Edit selected client rules, press Load selected client, edit tracker requirement, sender domains, ingest realm, Jira epic, ER sender filter, or ticker settings, then Save rules locally. These overrides stay in this Chrome profile; they do not edit the shared customer reference sheet.

The portal's fill dropdown offers auto (playbook), ID as title, ID + title, and ID + title + advertiser. A profile change refreshes the preview. ComScore ticker Reporting IDs and Titles use lowercase _t. SimulMedia has no special suffix and uses Jira epic DD-597. Internal Vizio requests ingest each file into both geniusdigital and vizio silos; verification checks both realms and the reply lists each file's commercial ID per realm (with pending IDs called out).

InMarket fills Advertiser, Brand, and Vertical from each tracker's InMarket Campaign Name (column D), not the client name. Blank campaigns leave existing fields untouched. Review each campaign in Check & preview before accepting fills. Tracker-context ranges such as campaign (1878-1883) are recognized; filename typos remain possible matches for your review.

If the wrong tracker appears, check the client and document identity before matching. Unknown ownership or missing document titles require your review. Reload the extension after an update to activate the latest UI and reference-cleanup protections.
