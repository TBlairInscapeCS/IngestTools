Find and download files?
Get the media - links, a delivery search, or whatever file page you have open.
Find files discovers candidates without downloading. Review the matches, then press Download files. Discovery tries every source in order: direct links from the email or tracker, a delivery search, then any open page that lists files - delivery lists, share folders, link pages, upload portals. If it lists your files, point at it. Only what's on screen counts - flip pages and press again to accumulate.
Search chooses client rules, automatic, Comcast email, Extreme Reach, Yangaroo, Downloads/Ingest, or open pages. Yangaroo uses the delivery email's per-spot Download links or an open Yangaroo page; the links land on matched rows so Download files pulls only requested spots. Comcast discovery reads open Outlook delivery messages without replacing the request. Local discovery finds only unique, recent request-ID-matched media and never moves it; duplicates need Pick & feed. Client rules can skip discovery in Run all.
Re-check re-runs the delivery check (inbox + delivery service) and arms a 5-min watch that chimes when files land. Overrides holds the manual paths: sender/day-window Extreme Reach search, open-pages-only capture, and the keyed ER API fetch.

Feed files and preview portal fills?
Fill the portal queue, then verify + draft Jira. Ingest/post stay your clicks.
Fills the Vizio Inscape Portal (portal.cognet.tv) ingest queue. Check & preview verifies the customer name against the playbook, lists queued files and shows exactly what would be written per row - Reporting ID, Title, Advertiser/Brand/Vertical, Fingerprint - before anything touches the page. Accept fills approves that preview: writes the cells and keeps watching for files dropped later. Feed files first checks Downloads/Ingest for unique recent request-ID matches (no move or manifest required), then streams available job files into the portal's file picker - batch one, the standard video+audio versions. The watcher builds _ticker versions on arrival; the status line shows the builds, and Feed ticker files queues them as the second, video-only ingest (separate batch per playbook) with fills applied automatically. Pick & feed lets you choose media anywhere on disk (files land in the job folder first). InMarket uses each matched row's InMarket Campaign Name (column D) for Advertiser, Brand, and Vertical; a blank campaign leaves existing fields untouched. Check these per-row values in the preview. Fills also recognize exact tracker File Name aliases; ambiguous matches stay untouched. The status counts actual filled files, and verification checks Advertiser, Brand, and Vertical as well as ID and Title. Accepting a new plan replaces the live fill plan for later drops. Explicit request row ranges exclude earlier sheet matches and their ticker flags from the fill plan and reply. Realm, Type, and Retention are never touched - defaults stand. Variant menu lets you explicitly choose Ingested + IDs after actual ingest. Trackerless confirmations never claim a sheet was updated and use the client's ticker suffix (ComScore: lowercase _t).
